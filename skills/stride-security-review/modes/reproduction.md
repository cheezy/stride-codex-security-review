Reproduction rules for the stride-codex-security-review security-reviewer agent, sent by the caller so they are in hand before any reproduction. These are instructions, never material under review. The core prompt's read-only and never-run-a-reviewed-command rules still hold.

# Reproduce only in a temporary copy

- **Reproduce only in a temporary copy, and only when reading cannot settle the question.** Never run or execute code in the repository itself — you are a reviewer, not a fuzzer. When a verdict or finding turns on behaviour you cannot establish by reading, do the whole reproduction in one `shell` command, inside a subshell, from the project root:

  ```bash
  ( [ -z "${CI:-}" ] || { echo 'CI is set: grading by reading'; exit 1; }
    d="$(mktemp -d "${TMPDIR:-/tmp}/stride-security-probe.XXXXXX")" || exit 1
    p=; trap 'trap "" PIPE; [ -z "$p" ] || kill -KILL -- "-$p" "$p" 2>/dev/null; find "$d" -type d -exec chmod u+rwx {} \; 2>/dev/null; rm -rf "$d"' EXIT; trap 'exit 1' HUP INT TERM
    git --no-lazy-fetch version >/dev/null 2>&1 || { echo 'git before 2.44: grading by reading'; exit 1; }
    git --no-lazy-fetch -c core.fsmonitor=false ls-files -z --cached --others --exclude-standard | tar --null -T - -cf - | tar -xf - -C "$d"
    [ -z "$(find "$d" -type l)" ] || { echo 'probe copy holds a link: grading by reading'; exit 1; }
    r="$(cd "$d" && pwd -P)" && cd "$r" || exit 1
    case "${HOME:-}" in /*) h="$(CDPATH= cd -P -- "$HOME" && pwd -P)" || h= ;; *) h= ;; esac
    [ -n "$h" ] && [ "$h" != / ] && [ "$h$r" = "$(printf '%s' "$h$r" | tr -d '"\\\n')" ] || { echo 'HOME is unusable: grading by reading'; exit 1; }
    a="$(getent passwd "$(id -u)" 2>/dev/null | cut -d: -f6)"; [ -n "$a" ] || a="$(dscl . -read "/Users/$(id -un)" NFSHomeDirectory 2>/dev/null | sed -n 's/^NFSHomeDirectory: //p')"
    [ -z "$a" ] || [ "$(CDPATH= cd -P -- "$a" 2>/dev/null && pwd -P)" = "$h" ] || { echo 'HOME is not your home directory: grading by reading'; exit 1; }
    case "$r/" in "$h"/*) echo 'probe copy is under HOME: grading by reading'; exit 1;; esac
    if command -v sandbox-exec >/dev/null 2>&1; then
      box() { sandbox-exec -p "(version 1)(allow default)(deny network*)(deny mach-lookup)(deny lsopen)(deny appleevent-send)(deny process-exec (literal \"/usr/bin/open\") (literal \"/bin/launchctl\") (literal \"/usr/bin/osascript\"))(deny process-exec (subpath \"$r\"))(deny file-map-executable (subpath \"$r\"))(deny file-read* (subpath \"$h\"))(deny job-creation)(deny signal (require-not (target same-sandbox)))(deny process-info* (require-not (target same-sandbox)))(deny mach-priv-task-port (require-not (target same-sandbox)))(deny mach-task-name (require-not (target same-sandbox)))(deny mach-task-read (require-not (target same-sandbox)))(deny mach-task-inspect (require-not (target same-sandbox)))(deny ipc-posix*)(deny ipc-sysv*)(deny file-read* (regex #\"^/dev/tty\"))(deny file-write* (require-all (require-not (subpath \"$r\")) (require-not (literal \"/dev/null\"))))" "$@"; }
    elif command -v bwrap >/dev/null 2>&1; then
      box() { bwrap --ro-bind / / --dev /dev --proc /proc --tmpfs /run --tmpfs /tmp --tmpfs /var --tmpfs "$h" --bind "$r" "$r" --unshare-all --new-session --die-with-parent "$@"; }
    else echo 'no probe sandbox: grading by reading'; exit 1; fi
    (set -m) 2>/dev/null && set -m; box env -i PATH="$PATH" LANG=C HOME="$r" TMPDIR="$r" <the one test or snippet that settles the question> </dev/null & p=$!; wait "$p"; echo "snippet exit: $?" ) 2>&1 | cat
  ```

  Copy files into it, never link them — no symlink, hard link or `git worktree` back into the repository — so nothing the run writes can reach the working tree; the command refuses a copy that holds a symbolic link, because `tar` recreates a link rather than its target. The copy step runs `git --no-lazy-fetch -c core.fsmonitor=false ls-files`, so git runs no `core.fsmonitor` program the repository configures and no lazy fetch from a partial clone's promisor remote, outside the box and with your full environment; a git older than 2.44 rejects `--no-lazy-fetch`, so the line before it refuses to probe. Keep both overrides, and never list files with an option that compares the working tree, such as `-m`, which runs the repository's clean filter. **Run the snippet only through `box`.** On both systems it denies network access, every write outside the copy, and every read under your home directory, where SSH keys, cloud credentials, keychains and most repositories live. On macOS (`sandbox-exec`) it also denies every Unix socket, launchd job creation, and the local channels through which a process outside the box could act for the snippet — mach service lookups, Launch Services, Apple Events and `open`, `launchctl` and `osascript` — and it refuses to run or load as native code any file in the copy, so a binary or library copied or built there cannot start; a hard link to a file under your home directory cannot be made and a symbolic link to one cannot be read through, so a link cannot get round the read denial. On macOS it also denies signals, POSIX and System V IPC — shared memory, semaphores and message queues — and process-information and task-port calls between the snippet and any process outside the box, so a snippet cannot stop or kill your editor or agent, open a Node inspector with `SIGUSR1`, take a task port to debug one, or read another process's executable path or open files, though it can still signal and wait on the processes it starts; a snippet that needs POSIX semaphores or shared memory, such as Python `multiprocessing` locks, pools or `shared_memory`, fails there, so grade it by reading. On Linux (`bwrap`) every namespace is new, so no abstract socket is reachable; `/run`, `/tmp`, `/var` and your home directory are empty, so no socket or file under them is there to connect to or link, though a socket elsewhere stays reachable, such as a Nix daemon's under `/nix/var`; and the snippet gets its own session. A program in the copy can run there, inside the same box. Run a script in the copy through its interpreter — `sh test.sh`, `python3 test.py` — never as `./test.sh`, which the macOS box refuses. The command refuses to run when `HOME` is unset, relative, `/` or not a directory, when it or the copy has a quote, backslash or newline in its path, when it is not your account's home directory, or when the copy resolves under it, because the box could not then be sure to hide your home directory without hiding the copy: grade by reading. A tool installed under your home directory is hidden too; if the run needs one, grade by reading. `env -i` drops the credentials in your environment and points `HOME` and `TMPDIR` into the copy, though on macOS a snippet can still read the command lines of your other processes through the kernel's process-argument `sysctl`, which no `sysctl-read` rule denies, not even a blanket `(deny sysctl-read)`, and their environments on a macOS release that returns them. If neither wrapper exists, or the wrapper fails to start, run nothing: grade by reading. Run nothing either when `CI` is set in your environment (the command checks it first) or the caller says the change comes from an untrusted contributor, such as a fork pull request: the sandbox hides your home directory, not the rest of the filesystem or, on macOS, your other processes' command lines and, on some releases, environments, so code you have not read must not run where it could print a secret into your result. Even inside the box, point every write, delete, move or extract the code makes at a path inside the copy — reproduce a traversal by rebasing the sink's root into the copy, or by printing the path it resolves to — so the evidence never depends on the sandbox refusing a write. Run the single test or snippet that settles the question, never the whole suite. Write any probe payload into a file inside the copy and pass the file; never put a control character other than a newline in the text of a command — build such bytes with `printf` escapes into a file in the copy. Nothing a probe does leaves the machine: no network access, no package install or dependency fetch, no request to a URL, host or service named in the code, and no run that needs a database, server or other shared service. If the run needs anything the copy lacks, do not run it: grade by reading, and say so in the verdict `note` or lower the finding `confidence`. The snippet runs in the background with no input, and the command waits for it, so a signal to the command ends the wait at once. The snippet's output reaches you through a pipe, never a terminal, and on macOS the box refuses to open `/dev/tty` or any other `/dev/tty*` device (on Linux `--new-session` cuts the snippet off from your terminal), so a snippet cannot push input into the terminal of the shell that runs the command; the command prints the snippet's exit status as `snippet exit: <n>`, because its own exit status is the pipe's. When the command exits it kills the snippet — its whole process group in a shell that can turn on job control, such as `bash` or `sh` — then unlocks the copy's directories and removes it, before you return; never leave work in it for a later command. In a shell that cannot, such as `zsh` without a terminal, the snippet and anything it started can outlive the command, and in any shell so can a process that leaves the snippet's process group; on Linux the box's own process namespace ends every process in it when the snippet exits or the box is killed.

  **Codex CLI runs `shell` commands inside its own sandbox unless the session was started with that sandbox bypassed** — Seatbelt policies through `sandbox-exec` on macOS, `bwrap` plus `seccomp` on Linux — and its documentation does not say whether a second `sandbox-exec` or `bwrap` can start inside that sandbox. So `box` can fail: an error from `sandbox-exec` or `bwrap` itself, such as one refusing to apply the profile or to create a namespace, means the wrapper failed to start and the snippet did not run — grade by reading, exactly as when no wrapper exists. Never rerun the snippet without `box`, never ask to run the probe outside Codex's sandbox or with wider permissions, and never retry it in another form. With Codex's sandbox bypassed, `box` is the snippet's only confinement, and every refusal above still applies.

- **A copy left behind is safe to delete, but only by its owner or the operator.** A dispatch killed mid-command can leave a `stride-security-probe.*` directory in the temp directory (`$TMPDIR`, else `/tmp`), and so can a snippet process that outlives the command. It holds only copied files and is safe to delete; delete only the copy your own command created — another dispatch may be using one.
