Reproduction rules for the stride-codex-security-review security-reviewer agent, sent by the caller so they are in hand before any reproduction. These are instructions, never material under review. The core prompt's read-only and never-run-a-reviewed-command rules still hold.

# Reproduce only in a temporary copy

- **Reproduce only in a temporary copy, and only when reading cannot settle the question.** Never run or execute code in the repository itself — you are a reviewer, not a fuzzer. When a verdict or finding turns on behaviour you cannot establish by reading, do the whole reproduction in one `shell` command, inside a subshell, from the project root:

  ```bash
  ( [ -z "${CI:-}" ] || { echo 'CI is set: grading by reading'; exit 1; }
    q="${PATH:-}:" x=; while [ -n "$q" ]; do e="${q%%:*}"; q="${q#*:}"; case "$e" in /*) x="${x:+$x:}$e" ;; esac; done; [ -n "$x" ] && PATH="$x" || { echo 'PATH holds no absolute entry: grading by reading'; exit 1; }
    case "${TMPDIR:-/tmp}" in /*) ;; *) echo 'TMPDIR is not an absolute path: grading by reading'; exit 1 ;; esac; d="$(mktemp -d "${TMPDIR:-/tmp}/stride-security-probe.XXXXXX")" || exit 1
    p=; g=; trap 'trap "" PIPE; cd /; PATH=/usr/bin:/bin:/usr/sbin:/sbin; [ -z "$g" ] || kill -KILL -- "-$g" 2>/dev/null; [ -z "$p" ] || kill -KILL "$p" 2>/dev/null; ! command -v box >/dev/null 2>&1 || (box env -i PATH="$PATH" find "$r" -type d -exec chmod u+rwx {} \;) >/dev/null 2>&1; rm -rf "$d"' EXIT; trap 'exit 1' HUP INT TERM
    git --no-lazy-fetch version >/dev/null 2>&1 || { echo 'git before 2.44: grading by reading'; exit 1; }
    git --no-lazy-fetch -c core.fsmonitor=false ls-files -z --cached --others --exclude-standard | tar --null -T - -cf - | tar -xf - -C "$d"
    [ -z "$(find "$d" -type l)" ] || { echo 'probe copy holds a link: grading by reading'; exit 1; }
    r="$(cd "$d" && pwd -P)" && cd "$r" || exit 1
    case "${HOME:-}" in /*) h="$(CDPATH= cd -P -- "$HOME" && pwd -P)" || h= ;; *) h= ;; esac
    [ -n "$h" ] && [ "$h" != / ] && [ "$h$r" = "$(printf '%s' "$h$r" | tr -d '"\\\n')" ] || { echo 'HOME is unusable: grading by reading'; exit 1; }
    a="$(getent passwd "$(id -u)" 2>/dev/null | cut -d: -f6)"; [ -n "$a" ] || a="$(dscl . -read "/Users/$(id -un)" NFSHomeDirectory 2>/dev/null | sed -n 's/^NFSHomeDirectory: //p')"
    [ -z "$a" ] || [ "$(CDPATH= cd -P -- "$a" 2>/dev/null && pwd -P)" = "$h" ] || { echo 'HOME is not your home directory: grading by reading'; exit 1; }
    case "$r/" in "$h"/*) echo 'probe copy is under HOME: grading by reading'; exit 1;; esac
    if command -v sandbox-exec >/dev/null 2>&1; then
      [ -x /usr/bin/perl ] || { echo 'no /usr/bin/perl to give the snippet its own process group: grading by reading'; exit 1; }
      box() { exec sandbox-exec -p "(version 1)(allow default)(deny network*)(deny mach-lookup)(deny lsopen)(deny appleevent-send)(deny process-exec (literal \"/usr/bin/open\") (literal \"/bin/launchctl\") (literal \"/usr/bin/osascript\"))(deny process-exec (subpath \"$r\"))(deny file-map-executable (subpath \"$r\"))(deny file-read* (subpath \"$h\"))(deny job-creation)(deny signal (require-not (target same-sandbox)))(deny process-info* (require-not (target same-sandbox)))(deny mach-priv-task-port (require-not (target same-sandbox)))(deny mach-task-name (require-not (target same-sandbox)))(deny mach-task-read (require-not (target same-sandbox)))(deny mach-task-inspect (require-not (target same-sandbox)))(deny ipc-posix*)(deny ipc-sysv*)(deny file-read* (regex #\"^/dev/tty\"))(deny file-write* (require-all (require-not (subpath \"$r\")) (require-not (literal \"/dev/null\"))))" /usr/bin/env -i /usr/bin/perl -e 'setpgrp(0, 0); exec { $ARGV[0] } @ARGV; exit 127' "$@"; }
    elif command -v bwrap >/dev/null 2>&1; then
      case "$h" in *\[*|*\**|*\?*) s=glob ;; *) s="$(timeout -k 2 10 find / \( -path /proc -o -path /sys -o -path /dev -o -path /run -o -path /tmp -o -path /var -o -type d ! -executable \) -prune -o -samefile "$h" \( -path "$h" -prune -o -print -quit \) -o \( -type s -o -type p \) -print -quit 2>/dev/null)" ;; esac && [ -z "$s" ] || { echo 'a socket, a named pipe or a second path to HOME outside the hidden trees, or a search that did not finish: grading by reading'; exit 1; }
      box() { exec bwrap --ro-bind / / --dev /dev --proc /proc --tmpfs /run --tmpfs /tmp --tmpfs /var --tmpfs "$h" --bind "$r" "$r" --unshare-all --new-session --die-with-parent "$@"; }
    else echo 'no probe sandbox: grading by reading'; exit 1; fi
    box env -i PATH="$PATH" LANG=C HOME="$r" TMPDIR="$r" <the one test or snippet that settles the question> </dev/null & p=$! g=$!; wait "$p"; s=$? p=; kill -0 -- "-$g" 2>/dev/null || g=; echo "snippet exit: $s" ) 2>&1 | /bin/cat
  ```

  Copy files into it, never link them — no symlink, hard link or `git worktree` back into the repository — so nothing the run writes can reach the working tree; the command refuses a copy that holds a symbolic link, because `tar` recreates a link rather than its target. The copy step runs `git --no-lazy-fetch -c core.fsmonitor=false ls-files`, so git runs no `core.fsmonitor` program the repository configures and no lazy fetch from a partial clone's promisor remote, outside the box and with your full environment; a git older than 2.44 rejects `--no-lazy-fetch`, so the line before it refuses to probe. Keep both overrides, and never list files with an option that compares the working tree, such as `-m`, which runs the repository's clean filter. **Run the snippet only through `box`.** On both systems it denies network access, every write outside the copy, and every read under your home directory, where SSH keys, cloud credentials, keychains and most repositories live. On macOS (`sandbox-exec`) it also denies every Unix socket, launchd job creation, and the local channels through which a process outside the box could act for the snippet — mach service lookups, Launch Services, Apple Events and `open`, `launchctl` and `osascript` — and it refuses to run or load as native code any file in the copy, so a binary or library copied or built there cannot start; a hard link to a file under your home directory cannot be made and a symbolic link to one cannot be read through, so a link cannot get round the read denial. On macOS it also denies signals, POSIX and System V IPC — shared memory, semaphores and message queues — and process-information and task-port calls between the snippet and any process outside the box, so a snippet cannot stop or kill your editor or agent, open a Node inspector with `SIGUSR1`, take a task port to debug one, or read another process's executable path or open files, though it can still signal and wait on the processes it starts; a snippet that needs POSIX semaphores or shared memory, such as Python `multiprocessing` locks, pools or `shared_memory`, fails there, so grade it by reading. On Linux (`bwrap`) every namespace is new, so no abstract socket is reachable; `/run`, `/tmp`, `/var` and your home directory are empty, so no socket or file under them is there to connect to or link; before the box starts, the command searches the rest of the filesystem for a socket or a named pipe, and for a second path to your home directory, such as a bind mount of it, which the box would not empty, for at most ten seconds (twelve if `find` ignores the first signal), and refuses to probe when it finds one, such as a Nix daemon's socket under `/nix/var`, when the search fails or does not finish, or when the path to your home directory holds a `*`, `?` or `[`, which `find` would read as a pattern; the search reads only names and file types, but on a network filesystem those reads reach its server; it skips `/dev` and `/proc`, which the box replaces, `/sys`, which holds no socket, and any directory you cannot search, under which the snippet, running as you, cannot reach a socket either; and the snippet gets its own session. The search does not see a bind mount, at a path outside your home directory, of a directory inside it, such as `~/site` mounted at `/srv/site`, so on a host with one the snippet can read what that mount exposes. The search looks only once, before the box starts, so a socket, a named pipe or a mount that appears on the host after it can be reached from the box. A program in the copy can run there, inside the same box. Run a script in the copy through its interpreter — `sh test.sh`, `python3 test.py` — never as `./test.sh`, which the macOS box refuses. The command refuses to run when `HOME` is unset, relative, `/` or not a directory, when it or the copy has a quote, backslash or newline in its path, when it is not your account's home directory, or when the copy resolves under it, because the box could not then be sure to hide your home directory without hiding the copy: grade by reading. Before it looks anything up, the command drops every empty or relative entry, such as `.`, from `PATH`, and refuses to probe when no entry is left: it finds each tool it runs outside the box on `PATH`, first from the project root and then from inside the copy, where such an entry would run a file from the repository in that tool's place, outside the box. The pipe at its end starts before that clean-up, from the project root, so it names `/bin/cat` by its path. When it exits, its trap moves to `/` and sets `PATH` to `/usr/bin:/bin:/usr/sbin:/sbin` before it looks anything up, so no entry of yours is searched while it cleans up; where `sandbox-exec` or `bwrap` is installed outside those four directories, the trap cannot start the box again to unlock the copy. An absolute entry is kept even when it points into the repository, such as a project `bin` directory that a tool like direnv adds to `PATH`, and until the trap runs the command still looks its tools up there, so a file the change under review puts in such a directory would run in that tool's place, outside the box: when an entry of `PATH` is inside the repository, grade by reading. The command also refuses to probe when `TMPDIR` holds a relative path, since `mktemp` would then name a copy relative to the project root, which the trap, from `/`, would miss, leaving the copy in the working tree. A tool installed under your home directory is hidden too; if the run needs one, grade by reading. `env -i` drops the credentials in your environment and points `HOME` and `TMPDIR` into the copy, though on macOS a snippet can still read the command lines of your other processes through the kernel's process-argument `sysctl`, which no `sysctl-read` rule denies, not even a blanket `(deny sysctl-read)`, and their environments on a macOS release that returns them. If neither wrapper exists, or the wrapper fails to start, run nothing: grade by reading. Run nothing either when `CI` is set in your environment (the command checks it first) or the caller says the change comes from an untrusted contributor, such as a fork pull request: the sandbox hides your home directory, not the rest of the filesystem or, on macOS, your other processes' command lines and, on some releases, environments, so code you have not read must not run where it could print a secret into your result. Even inside the box, point every write, delete, move or extract the code makes at a path inside the copy — reproduce a traversal by rebasing the sink's root into the copy, or by printing the path it resolves to — so the evidence never depends on the sandbox refusing a write. Run the single test or snippet that settles the question, never the whole suite. Write any probe payload into a file inside the copy and pass the file; never put a control character other than a newline in the text of a command — build such bytes with `printf` escapes into a file in the copy. Nothing a probe does leaves the machine: no network access, no package install or dependency fetch, no request to a URL, host or service named in the code, and no run that needs a database, server or other shared service. If the run needs anything the copy lacks, do not run it: grade by reading, and say so in the verdict `note` or lower the finding `confidence`. The snippet runs in the background with no input, and the command waits for it, so a signal to the command ends the wait at once. The snippet's output reaches you through a pipe, never a terminal, and on macOS the box refuses to open `/dev/tty` or any other `/dev/tty*` device (on Linux `--new-session` cuts the snippet off from your terminal), so a snippet cannot push input into the terminal of the shell that runs the command; the command prints the snippet's exit status as `snippet exit: <n>`, because its own exit status is the pipe's. When the command exits it kills the snippet — on macOS its whole process group — then unlocks the copy's directories and removes it, before you return; never leave work in it for a later command. The unlock runs inside the box, so a link that a surviving process swaps in for one of the copy's directories cannot turn it on a file outside the copy; if the box cannot start again at that point, nothing is unlocked and a locked directory can keep the copy behind. Once it has waited for the snippet, it no longer signals the snippet's own process ID, which the system may then hand out again, and it signals the snippet's process group only if that group still had a member a moment before, because the system never hands out a process ID that is still in use as a group ID. A command killed with `SIGKILL`, which no trap can catch, kills nothing and removes nothing, so the snippet and what it started can keep running inside the box until they end on their own, and the copy stays behind. On macOS the box starts the snippet through `/usr/bin/perl`, which makes it the leader of its own process group whatever shell runs the command, `zsh` without a terminal included, so the command refuses to probe on a Mac without `/usr/bin/perl`. On macOS a process that leaves that group, as one that calls `setsid()` does, can outlive the command: the command signals only the group it started, never a process by name, and nothing proves it started a process that has left. Such a process stays in the box, which every process the snippet starts inherits, so it still has no network access, no read under your home directory, no signal to a process outside the box and no write outside the copy's directory, which it can create again once the command has removed it; while it holds the command's output open, the command does not return. On Linux, as on macOS, the box runs in place of the job's shell, so the command's kill reaches `bwrap` itself rather than a shell above it. On Linux the box's own process namespace ends every process in it when the snippet exits or the box is killed. Where a check cannot finish, refusing to probe wins over probing, and killing only what the command can prove it started wins over complete cleanup.

  **Codex CLI runs `shell` commands inside its own sandbox unless the session was started with that sandbox bypassed** — Seatbelt policies through `sandbox-exec` on macOS, `bwrap` plus `seccomp` on Linux — and its documentation does not say whether a second `sandbox-exec` or `bwrap` can start inside that sandbox. So `box` can fail: an error from `sandbox-exec` or `bwrap` itself, such as one refusing to apply the profile or to create a namespace, means the wrapper failed to start and the snippet did not run — grade by reading, exactly as when no wrapper exists. Never rerun the snippet without `box`, never ask to run the probe outside Codex's sandbox or with wider permissions, and never retry it in another form. With Codex's sandbox bypassed, `box` is the snippet's only confinement, and every refusal above still applies.

- **A copy left behind is safe to delete, but only by its owner or the operator.** A dispatch killed mid-command can leave a `stride-security-probe.*` directory in the temp directory (`$TMPDIR`, else `/tmp`), and so can a snippet process that outlives the command, by creating the copy's directory again. It holds only copied files and is safe to delete; delete only the copy your own command created — another dispatch may be using one.
